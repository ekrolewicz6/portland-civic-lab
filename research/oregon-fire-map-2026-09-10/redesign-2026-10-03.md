# Fire in Oregon: redesign, October 3, 2026

Edan asked for a complete redesign of `/oregon-fire/landscapes`, the other fire subpages, and the main guide: more engaging, easier to follow, simple and elegant. This note records what changed and the rules the new design follows. No facts, sources, anchors or URLs changed. Nothing has been deployed.

## What was wrong

The fire section had grown across several sessions into five stylesheets (about 100 KB of one-line rules) that overrode each other. The root rule set the whole section to 15px with 10px labels, against a site base of 17 to 26px. On the landscapes page the heading and its paragraph landed in different grid rows, and four cards were squeezed to about 130px each so the text wrapped a word per line. The main guide ran in a 1,080px column inside a 1,440px page, with a different card colour for nearly every figure.

## What it is now

One stylesheet, `src/app/(public)/oregon-fire/fire.css`, imported once by the shell and the main page. The five old files are deleted.

- **Three surfaces.** Paper for the page, one tinted plate for figures, forest green for the hero and the few moments that should stop the eye (the tree-ring history, the Whetstone acreage, the place finder, the closing band).
- **One layout.** Every section is a label rail on the left (chapter number or eyebrow) and content on the right. Text holds a 36rem measure; figures break out to the full page width.
- **Type.** Cormorant Garamond for display, DM Sans for reading, JetBrains Mono for small labels. Everything is in rem so it follows the site's fluid root size. Nothing renders below 12px.
- **One step pattern.** Every numbered sequence (the four investigation questions, plan to authorization to status, prepare/wait/burn, boundary/severity/follow-up) uses the same `.fire-steps` row under a rule.
- **Sticky section navigation with the current section marked** (`FireSectionNav`), on the guide and on every subpage, so a reader always knows where they are on a long page.
- **A ridgeline closes each hero** (`FireRidge`) and hands off to the paper.
- **Base element rules use `:where(.fire-page)`** so a component class always wins. This is what stops the cascade fights that produced the old pile.

## Rules for future edits

1. Add to `fire.css`; do not create a second stylesheet for a new subpage.
2. Use the tokens (`--f-*`). Do not introduce a new background colour for a figure.
3. Size in rem. Check the 12px floor at a 390px viewport.
4. A new sequence uses `.fire-steps`. A new figure heading uses `.fire-figure-head`.
5. Inside a `.fire-long-chapter`, subheadings are `h3` or lower. A test asserts the eight chapter `h2`s are the only ones.
6. Keep the class hooks the tests use (`.fire-long-chapter`, `.fire-hero-image-pair`, `.fire-story-nav a`, `.fire-explorer`, `.fire-result`, `.fire-cost-*`, and the section ids).

## Copy changes

Limited to the landscapes page, to remove em dashes and an "X, not Y" construction per the site's writing rules. Meaning is unchanged: "does—or does not—become" is now "does or does not become"; "possible—and the evidence" is now "possible, and the evidence"; "places to investigate, not ranked projects" is now "three places to investigate. We have not ranked them." The three pilot criteria that were buried in a sentence are shown as a checklist with the same closing statement that no candidate has passed yet.
